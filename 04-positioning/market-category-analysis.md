## Candidate Categories

### 1. Automotive engineering R&D services (ESP): existing, head-to-head
- **Buyer expectations:** scale and ramp-up, TISAX, ASPICE CL2/3 record, panel listing, OEM references, end-to-end SDV coverage, "AI productivity".
- **Leaders:** KPIT, Tata Elxsi, LTTS, Capgemini, Akkodis, DXC/Luxoft, HCLTech; 28 providers in Everest's SDV matrix [Data, H].
- **Size:** USD 150.7B (2025) outsourced, IMARC; total auto engineering spend USD 240-260B, Everest [Data, L-M; definitions differ]. Cyclical: −24-25% in 2025 per KPIT [Data, H].
- **Fit:** **Weak.** The founders miss every table stake; the frame hides all differentiators and invites a rate-card comparison with India (USD 25-45/h [Estimate, L-M; Phase 3]).

### 2. AUTOSAR BSW integration services: subcategory
- **Buyer expectations:** deep MICROSAR / tresos / RTA-CAR knowledge, MCAL experience, a working build on target.
- **Leaders:** stack vendors' services, KPIT (Qorix), Avelabs, many freelancers.
- **Size:** not sized; AUTOSAR software reports USD 3.5-7.9B disagree >2x [Data, L].
- **Fit:** **Moderate.** The founders' core skill, but Vector's AI configuration is commoditising the task and it collides head-on with Avelabs. **Use as the year-2 expansion frame.**

### 3. AUTOSAR security integration ("Secure ECU integration"): subcategory, recommended
- **Buyer expectations:** on-target crypto stack, SecOC, KeyM, HSM, secure boot; key provisioning; TARA traceability; MCU-family experience; assessor-ready work products.
- **Leaders:** product-led bundles (ETAS/ESCRYPT, Vector, EB, FESCARO, Autocrypt); ESPs offering it as one capability among many; consultancies that stop at paper [Data, M].
- **Density:** Low-Medium for *services-led, cross-stack, fixed-price, evidence-included* integration; none found offering exactly that [Data + Opinion, M].
- **Size / growth:** within automotive cybersecurity, USD 3.9-6.9B in 2026, 15-20% CAGR; no services split [Data, M on direction, L on level]. Regulation-forced (R155/R156 since Jul 2024; GB 44495 new types since Jan 2026, all types Jan 2028) [Data, H].
- **Fit:** **Strong.** Every differentiator answers an existing buyer question.

### 4. AI-native / agentic engineering services ("Services-as-Software"): emerging
- **Buyer expectations:** outcome pricing, speed, transparency on AI control, tool confidence.
- **Leaders (automotive vocabulary):** KPIT Mobility Agentic AI suite, Tata Elxsi DevStudio.ai, DXC "AI-powered SI", LTTS "AI-led ER&D" [Data, H].
- **Fit:** **Weak for buyers, strong for investors.** Buyers don't source against it, and 5 of 9 competitor homepages already lead with AI [Data, H].

### 5. Compliance evidence (ASPICE / ISO 21434 work products): existing
- **Leaders:** AI-TARA tools (ThreatZ/VxLabs, Ketryx, C2A), consultancies (UL, SwRI, TÜV).
- **Fit:** **Weak as a category** (commoditising, frames the founders as paperwork); **strong as a differentiator inside Category 3** ("evidence included").

## Recommendation
**Position into the subcategory "AUTOSAR security integration".** Big fish, small pond: the founders can lead it because no services-led provider owns it, and buyers already have the vocabulary (SecOC, HSM, secure boot, 21434), so only the packaging is new. **Category creation is not warranted** [Opinion, M].

Why [Opinion, M]:
1. The frame makes each differentiator obvious: on-target vs paper (tools, consultants), the customer's stack vs one vendor's (vendors, FESCARO), evidence included vs hours (freelancers), named engineers vs anonymous teams (ESPs).
2. Demand is forced by regulation, so it sells in the ER&D trough (B2).
3. It rides on Vector's AI rather than fighting it.
4. A bounded package fits how German Tier 1s already buy BSW work (Werkvertrag) and can be subcontracted through approved ESPs [Data, M].

**Category narrative (Deep mode):** "ECU security has moved from a feature to a type-approval condition, but nobody is accountable for making it work across the silicon, the stack and the evidence. Vendors secure their own products, freelancers sell hours, tools write documents. AUTOSAR security integration is the job in between, and it is now a deadline." [Opinion, M]

**Category ladder:**
1. **Now (wedge):** AUTOSAR security integration.
2. **Year 2+ (Gold niche):** evidence-included AUTOSAR BSW integration packages, carrying the wedge's references.
3. **Investor narrative throughout:** Services-as-Software for safety- and security-critical automotive software.

## Implementation
- **Category label (buyer-facing, use everywhere):** "AUTOSAR security integration". It mirrors job-ad and freelance-project language ("AUTOSAR Security", "Classic AUTOSAR Security Stack", "AUTOSAR Cybersecurity") [Data, M]; no public RFQ documents were found.
- **Package / offer name direction (Phase 5):** "Secure ECU package" (B1's "Secure ECU integration"); test both terms in discovery calls.
- **Tagline direction:** outcome + bundle: "Your ECU's security stack, working on target. Evidence included."
- **Buyer expectations to meet:** on-target acceptance test; the customer's stack and MCU; traceability to TARA goals; SEC.1-4 (ASPICE for Cybersecurity PAM 2.0) and SWE evidence structure.
- **Expectations to manage:** key provisioning at end-of-line (not yet in the founders' record; partner or hire); stacks beyond Vector/ETAS and MCUs beyond Infineon (state scope openly); TISAX (in progress, or delivered via a prime).
- **Investor framing:** "Services-as-Software" backed by package reuse per MCU family, gross-margin trend, share of agent-produced work products, and the benchmark/evidence harness as IP. Services firms trade at about 1-4x sales; investors test gross margin before granting software multiples [Data, L-M; B1].

## Red Flags
- **Small pond with no services sizing.** Assume single-digit EUR millions addressable for a start-up at first [Estimate, L]. The expansion frame (Category 2) is needed for venture scale.
- **Product-led bundles are the trusted default** for buyers already standardised on one vendor's HSM [Opinion, M].

## Yellow Flags
- "Cybersecurity" in the label can trigger IDS/VSOC expectations; "AUTOSAR security integration" reduces that risk.
- Analyst lenses (ISG, Everest, Zinnov) have no subcategory here, so no "Leader" badge is available; credibility must come from references and assessors [Data, M].
- FESCARO could expand to Europe or add stack-neutral services.

## Data Gaps
- No sizing of security-integration services; no bottom-up estimate yet (ECU programmes with HSM per year × person-months × rate).
- No public Tier 1 RFQ structure (panel → RFQ → nomination).
- Whether buyers say "AUTOSAR security integration", "security BSW integration" or "Secure ECU".
- Private valuation comparables for AI-enabled engineering-services start-ups.
